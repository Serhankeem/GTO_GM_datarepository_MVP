# PR #1 저장소 진단과 결정

## 기준 및 구조 문제

- 확인한 초기 HEAD: `7aa1b59485eebd7a3fb906527ac20058fc301d96`. `main`은 변경하지 않고 `feat/ggto-pages-ui-foundation-v01`에서 개발한다.
- 실제 origin은 `Serhankeem/GTO_GM_datarepository_MVP`. 요청의 `ggto-global-datahub`는 Git 조회 시 Repository not found였다. 사용자가 현재 연결된 저장소 사용을 명시적으로 선택했다.
- 초기 파일은 모두 루트에 있었으며 README의 config/docs/workflow 경로는 존재하지 않았다. `.nojekyll`과 `.gitignore`도 없었다.
- `download`는 다운로드 데이터가 아니라 ignore 규칙 텍스트였다. 내용을 `.gitignore`로 복원했다. `download (1)`은 0바이트 빈 파일로 제거했다.
- index.html에 CSS·JS·두 종류 JSON이 인라인 중복되어 있었다. 이제 스타일·로직·계산 모듈과 JSON을 분리하고 config/data에서 한 번 로딩한다.
- 초기 CSV 지표 사전은 8행의 구버전 정의이고 JSON은 확정 15개였다. 초기 CSV와 5행 출처 대장을 docs/archive에 원문 보존하고 현재 CSV는 canonical config에서 재생성했다. 초기 CSV의 라이선스/확인 표시는 검증된 권리로 승계하지 않는다.
- validate_demo.py의 기본 입력은 존재하지 않는 docs/demo_monthly.csv였다. scripts로 이동하고 기본 입력을 data로, 출력은 /tmp/ggto-validation으로 수정했다.

## 기존 구현 / 미구현

기존 구현: 메뉴 9개, 전국 합성 월별 추이·YoY·CSV, 국가별 모의 비중, 7개 시군 모의지수, 자원 7개 필터, 보고서 안내 링크 4개, 15개 지표 목록. 실제 JSON 파일은 런타임에서 사용하지 않고 인라인 복사본을 사용했다.

기존 미구현: 공식 통계·국가별 월별 인원·지역 시계열·카드 소비 관측·운항 관측·실제 OTA URL·검증된 보고서 서지·수집/승인/정정 시스템. 초기 소비·항공의 하드코딩 숫자는 기간·출처 관측이 없어 이번 연결 대기 화면으로 대체했다.

## 요청/명세 차이 해결

- 기존 프롬프트 브랜치 feat/pages-prototype-polish-v01 대신 최신 요청 브랜치명을 사용한다.
- 기존 국가별 시장분석 메뉴를 방한통계의 국가별 모의 비중 패널로 통합해 요청한 핵심 8개 화면을 구성했다. 15개 지표 코드·ID·정의 JSON은 변경하지 않았다.
- 31개 시군 공식 숫자는 원자료 매핑 전 결측이라는 명세를 유지한다. 기존 7개 모의지수만 별도 DEMO 열에 보존하고 새 숫자를 생성하지 않는다.
- '모든 필터 반영'은 자료가 지원하는 차원에 한해 적용한다. 국가 비중은 기준기간 없는 스냅샷이므로 월별 전국 시계열과 결합하지 않는다. 지역의 국가별·기간별 관측, 소비·운항 관측은 없으므로 해당 필터를 비활성화하고 이유를 표시한다.
- 기존 시장 change 값은 비교기간과 정의가 없어 국가별 성장률로 표시하지 않는다. 원본 JSON에는 보존한다.
- README의 Pages main/root 설명은 문서상 가정이다. 실제 Pages API 읽기는 네트워크 차단으로 아직 확인하지 못했다. 배포 설정은 변경하지 않았으며 루트/프로젝트 하위 경로는 로컬 브라우저로 검증한다.
